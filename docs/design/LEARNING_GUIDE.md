## 一、这个项目到底是什么（30 秒版）

一个 **"拍照识别害虫 → 自动给防治建议"** 的 Web 系统。

```
农户拍一张照片
   │
   ▼
🌐 前端页面（HTML/CSS/JS）        —— 选图、展示结果、对话
   │  HTTP 请求
   ▼
⚙️ 后端服务（FastAPI）            —— 接请求、调模型、调知识库
   │
   ├─▶ 🧠 深度学习模型（YOLO）    —— 认出图里是什么害虫 + 框出来
   ├─▶ 📚 知识库 + 大模型（RAG）  —— 查资料、生成防治建议
   └─▶ 🗄️ 数据库（SQLite）        —— 记录历史、统计
   │
   ▼
农户看到：结果图 + 每种害虫的防治方法 + 天气预警
```

**整个项目 = 前端（怎么展示）+ 后端（怎么调度）+ 三个智能（识别/知识/对话）**

## 三、核心主线：一次请求的完整旅程（最重要！）

把下面这个故事看懂，项目就通了 80%。以"用户上传一张图"为例：

```
① 用户在页面点"上传图片"
     前端 JS 把图片打包 → fetch 发到 /detect/image
② FastAPI 收到请求（main.py 的 detect_image 函数）
     - 校验文件类型/大小
     - 把 CPU 密集的推理丢到线程池（await asyncio.to_thread）
③ YOLO 模型推理（inference_engine + best.pt）
     - 图片变成 640×640 张量 → 神经网络前向 → 输出一堆候选框
     - 每个框：类别 + 置信度 + 坐标
④ 后处理（main.py）
     - 类别自适应阈值过滤（低置信度丢弃）
     - 开放集识别：都不像 16 类 → 提示"未知虫种"
     - 画框 → 保存结果图 → 写 SQLite 历史
⑤ 前端拿到结果，展示：结果图 + 害虫列表 + 每种害虫的按钮
⑥ 用户输入"这些怎么防治" → 前端带着害虫名单 → /qa/ask-stream
⑦ 后端 RAG 检索（semantic_kb）：
     - 把问题转成向量 → FAISS 找最像的知识块
     - BM25 关键词兜底 → 混合排序
⑧ 大模型生成（knowledge_base）：
     - 把"知识块 + 问题 + 系统提示"发给 LLM
     - LLM 流式吐字 → 后端以 SSE 逐块转发
⑨ 前端打字机逐字显示回答 + 资料来源
```

**一句话总结**：`前端 fetch → FastAPI 调度 → [YOLO 识别 | RAG+LLM 回答] → 流式返回 → 前端展示`

## 四、分块核心讲解

### 1️⃣ Python 基础（地基中的地基）
- **类（class）**：项目里每个功能都是一"类"，如 `SemanticKnowledgeBase`（知识库）、`PestControlAgent`（助手）。类 = 数据 + 方法打包。
- **模块（import）**：`backend/` 里每个 `.py` 是一个模块，`from backend.main import ...` 就是"借用别人写好的功能"。
- **字典（dict）**：项目里大量 `{"key": value}`，比如害虫 JSON 就是字典。
- ✅ 掌握标准：能看懂 `backend/main.py` 里每个函数在干嘛。

### 2️⃣ FastAPI 异步（Web 后端）
- **路由**：`@app.post("/detect/image")` = "当有人 POST 这个地址，就执行下面的函数"。
- **async / await**：异步 = "不等结果先干别的"。本项目关键优化：把耗时的推理用 `await asyncio.to_thread(...)` 丢到线程池，避免一个慢请求卡死整个服务器。
- **Pydantic**：`class QARequest(BaseModel)` = "规定请求必须长什么样"，自动校验。
- ✅ 掌握标准：能说清"一个请求进来，经过哪几层返回"。

### 3️⃣ YOLO 深度学习（识别害虫）
- **神经网络**：一堆"数学神经元"层层连接，输入像素、输出答案。训练 = 喂大量图片让网络自己学。
- **目标检测**：不光分类，还要**框出位置**。YOLO 把图分成网格，每个格子预测"这里有没有虫 + 是什么 + 多大"。
- **指标 mAP**：衡量"又准又全"。Precision=框出来的有多少是对的；Recall=该框的有多少框到了。mAP 综合两者。
  - 本项目蒸馏后 mAP@0.5 从 49.4% → 74.6%。
- **置信度**：模型对自己判断的把握（0-100%）。本项目按害虫类别设不同阈值（特征明显的用高阈值）。
- ✅ 掌握标准：能解释"为什么灰飞虱难检测"（小目标 + 易混淆）。

### 4️⃣ 知识蒸馏（为什么又小又准）
- **大模型（教师 v11m，20M 参数）** 先学得好 → 它的"经验"（软标签/特征）传给**小模型（学生 v11n，2.6M）**。
- 类比：老教师带新学生，新学生抄老师的"答题思路"而非死记答案。
- 收益：**保持小模型的轻快（CPU 可跑），却接近大模型的精度**。
- ✅ 掌握标准：能解释"为什么不直接部署大模型"（CPU 服务器跑不动）。

### 5️⃣ RAG + LLM（问答是怎么"会"的）
- **向量**：把文字转成"一串数字"，语义相近的向量距离近（"叶子卷了"≈"稻纵卷叶螟"）。
- **FAISS**：快速找"最像的向量"的数据库 → 从 80 个知识块里捞最相关的。
- **BM25**：传统关键词匹配（"防治"就找含"防治"的），作为兜底。
- **RAG（检索增强生成）**：先把相关知识查出来，再让 LLM 基于这些资料回答 → 答案有依据、不乱编。
- **流式 SSE**：LLM 一个字一个字吐，后端逐块转发，前端打字机显示（不用等全部）。
- ✅ 掌握标准：能画出"问题 → 检索 → 生成"的链路。

### 6️⃣ 前端（HTML/CSS/JS）
- **HTML** = 结构（有哪些按钮/框），**CSS** = 样式（好看），**JS** = 行为（点击干什么）。
- **fetch**：JS 发 HTTP 请求的 API（`fetch('/detect/image', {method:'POST', body})`）。
- **流式读取**：`response.body.getReader()` 逐个读返回块 → 实现打字机。
- ✅ 掌握标准：能在 `app.js` 里找到"上传图片后做了什么"。

### 7️⃣ Git / Docker（交付工具）
- **Git**：版本管理。`add`（暂存）→ `commit`（存档）→ `push`（上传 GitHub）。`git mv` 移动文件会保留历史。
- **Docker**：把"环境 + 代码 + 依赖"打包成镜像，服务器一条命令跑起来（`docker compose up -d`），解决"我这能跑你那跑不了"。
- ✅ 掌握标准：会提交代码、会用 Docker 部署。

## 六、常见误区

1. **误区：要背 API** → 不用，知道"哪个文件干什么、去哪找"就行。
2. **误区：先学 AI 再学后端** → 应该先走通"请求旅程"，再深入各块。
3. **误区：mAP 越高越好** → 本项目更看重"CPU 能跑 + 部署可用"。
4. **误区：文档都要读完** → 按需查，`docs/README.md` 是导航入口。
5. **误区：一次全掌握** → 分块学，每块能"讲给别人听"就算掌握。
