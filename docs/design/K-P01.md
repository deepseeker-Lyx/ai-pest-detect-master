## 一、项目总览

### 1.1 一句话描述

**基于 YOLOv11 的水稻害虫智能检测系统**——用户上传稻田照片，系统自动识别 16 种水稻害虫，结合 DeepSeek 大模型提供防治建议，并基于地理位置推送天气和虫害预警。

### 1.2 核心能力

```
┌─────────────────────────────────────────────────────────────┐
│                   用户入口（浏览器/手机）                      │
│                                                             │
│  ① 图片检测 ──→ YOLOv11 识别 16 种害虫                       │
│                ──→ 置信度打分 + 不确定合并                     │
│                ──→ 标注结果图 + 害虫列表                      │
│                                                             │
│  ② 知识问答 ──→ TF-IDF 检索本地知识库                         │
│                ──→ DeepSeek 大模型生成回答                    │
│                ──→ Markdown 渲染 + 结构化展示                  │
│                                                             │
│  ③ 天气预警 ──→ 浏览器定位 / IP 定位                          │
│                ──→ Open-Meteo 获取实时天气                    │
│                ──→ 规则引擎评估虫害风险                        │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 目标用户

| 用户类型 | 使用场景 | 核心需求 |
|---------|---------|---------|
| 水稻种植户 | 田间巡检时拍照 | 快速知道"这是什么虫？怎么治？" |
| 农技人员 | 下乡指导时使用 | 获取准确的防治建议和气象信息 |
| 农业学生 | 学习研究 | 理解 AI 在农业中的应用 |

## 三、模块详解

### 3.1 核心模块：`backend/main.py`

| 属性 | 说明 |
|------|------|
| **职责** | FastAPI 应用入口，路由注册，检测逻辑编排 |
| **关键函数** | `_run_detect()`、`_make_detection()`、`_merge_uncertain_detections()` |
| **关键类** | `Detection`（Pydantic 模型）、`DetectResponse` |
| **代码量** | ~500 行 |
| **依赖** | ultralytics, fastapi, opencv, numpy |

**核心逻辑流**：
```
detect_image()
  → 保存上传图片
  → _run_detect(str_path)
    → model(img, conf=0.25, augment=True)[0]  # YOLO 推理
    → results.plot()                           # 绘制标注图
    → 按类别自适应阈值过滤检测框
    → _merge_uncertain_detections()            # 合并重叠框
  → 返回 DetectResponse
```

### 3.2 知识库：`backend/knowledge_base.py`

| 属性 | 说明 |
|------|------|
| **检索方式** | TF-IDF 关键词匹配（余弦相似度） |
| **数据源** | `knowledge/pests/*.json`（16 种害虫） |
| **LLM 调用** | OpenAI 兼容协议（当前用 DeepSeek） |
| **流式输出** | SSE (Server-Sent Events) |

**检索增强**：不同类型的问题自动加权——问到"防治"时防治建议类目分数 +0.45，问到"危害"时危害症状类目 +0.35。

**系统提示词**：经过多轮迭代，当前提示词包含 9 条要求（问题分析→详细解答→实操建议→注意事项 四段式结构）。

### 3.3 语义知识库：`backend/semantic_kb.py`（增强模块）

| 属性 | 说明 |
|------|------|
| **技术** | sentence-transformers + FAISS + BM25 |
| **模型** | shingib624/text2vec-base-chinese |
| **模式** | hybrid（语义 + 关键词混合检索）|
| **状态** | ✅ 已加载（80 个知识块） |

**三层检索架构**：
```
用户问题
  │
  ├─ ① FAISS 语义检索（768 维向量）
  ├─ ② BM25 关键词检索
  │
  └─ ③ RRF 融合 + 重排序
```

### 3.4 AI Agent：`backend/pest_agent.py`（增强模块）

| 属性 | 说明 |
|------|------|
| **框架** | ReAct（Reasoning + Acting 循环） |
| **工具** | search_knowledge、analyze_risk、format_report |
| **输出** | 结构化诊断报告（含风险等级） |

**工作流**：
```
用户输入 → Thought（思考需要什么信息）
         → Action（检索知识库）
         → Observation（分析检索结果）
         → Thought（结合置信度评估风险）
         → Action（生成防治方案）
         → Final Answer（结构化报告）
```

### 3.5 推理引擎：`backend/inference_engine.py`（增强模块）

| 属性 | 说明 |
|------|------|
| **功能** | 自适应后端选择、感知哈希缓存、推理时间线 |
| **缓存** | LRU + dHash 感知哈希（128 张容量） |
| **后端** | 自动检测 CUDA → MPS → ONNX → CPU |
| **状态** | ✅ 已加载（ONNX 后端）|

**注意**：当前检测主流程已绕过引擎的 CLAHE 预处理（因发现 CLAHE 降低检测精度），引擎仅用于 `detect_base64`（移动端摄像头）场景的缓存加速。

### 3.6 天气服务：`backend/weather_service.py`（新增）

| 属性 | 说明 |
|------|------|
| **天气源** | Open-Meteo（免费，无需 Key） |
| **定位方式** | 浏览器定位 → IP 定位（ip-api.com）→ 默认坐标 |
| **风险评估** | 基于 16 种害虫的温湿度适生条件规则引擎 |
| **通用预警** | 高温干旱、适温高湿、连续降雨等 |

### 3.7 前端：`frontend/`

| 文件 | 职责 | 关键功能 |
|------|------|---------|
| `index.html` | 页面结构 | 响应式 meta、安全区适配、图标库 |
| `style.css` | 样式 (~980行) | CSS 变量体系、深浅色、动画、移动端适配 |
| `app.js` | 交互逻辑 (~680行) | 上传检测、流式问答、天气预警、Markdown 渲染 |

**前端亮点功能**：
- Markdown 到 HTML 渲染（标题、粗体、列表、分割线）
- 对数衰减进度条（`requestAnimationFrame` 驱动）
- 检测列表交错入场动画
- 不确定检测的"两种可能"展示
- 检测后快捷操作按钮（零接触引导）

## 四、数据流全景

### 4.1 图片检测流程

```
用户选择图片
  │
  ├─ 前端校验格式（JPG/PNG/BMP/GIF/WebP）
  │
  ├─ POST /detect/image (FormData)
  │
  ├─ 后端保存到 uploads/
  │
  ├─ YOLO 推理 (conf=0.25, augment=True)
  │     ├─ 预热模型（首次）
  │     ├─ 多尺度推理（TTA）
  │     └─ NMS 后处理
  │
  ├─ 类别自适应阈值过滤
  │     └─ 低分框 → 丢弃
  │
  ├─ 重叠框合并
  │     ├─ IoU > 0.5 + 置信度差 < 20% → 备选项
  │     └─ 主框置信度 ≥ 75% → 不显示备选项
  │
  ├─ 绘制标注结果图 → 保存到 results/
  │
  ├─ 返回 DetectResponse
  │
  └─ 前端渲染
        ├─ 检测卡片（统计 + 图片 + 列表 + 快捷按钮）
        ├─ 天气信息栏（定位 → 天气 → 虫害风险）
        └─ 输入框占位更新
```

### 4.2 问答流程

```
用户输入问题
  │
  ├─ POST /qa/ask-stream (SSE)
  │
  ├─ 知识库检索（TF-IDF，Top-4）
  │
  ├─ 流式调用 DeepSeek API
  │     ├─ 系统提示词（9 条要求）
  │     ├─ 知识库内容（上下文）
  │     └─ 用户问题
  │
  ├─ SSE 流返回
  │     ├─ data: {"text": "..."}  ← 逐字输出
  │     └─ data: {"sources": [...]}  ← 资料来源
  │
  └─ 前端渲染
        ├─ 进度条（对数衰减 → 跳满）
        ├─ Markdown 渲染
        └─ 资料来源脚注
```

## 七、明日迭代规划

### P0：检测历史与本地存储

**目标**：用户刷新页面后能看到之前的检测记录。

**方案**：前端 `localStorage` 存储最近 20 条检测记录。

实现步骤：
```
① 检测成功后，将检测结果（害虫名、置信度、时间）存入 localStorage
② 页面加载时，从 localStorage 读取历史记录
③ 在消息区域顶部添加"历史记录"折叠面板
④ 点击历史记录可重新查看检测详情
```

**预计耗时**：3 小时  
**前置条件**：无（纯前端改动）

### P1：首屏加载体验优化

**目标**：减少模型加载时的白屏等待感。

**方案**：启动时显示加载进度页面。

```
① 后端新增 /status/loading 端点，返回模型加载进度
② 前端在页面加载时轮询该端点
③ 显示"正在加载 YOLO 模型... (85%)" 进度条
④ 加载完成后自动显示主界面
```

**预计耗时**：2 小时

### P1：批量检测对比（尝试实现）

**目标**：支持同时上传多张图片，对比检测结果。

**方案**：
```
① 前端支持多文件选择（fileInput 加 multiple 属性）
② 后端新增 POST /detect/batch 端点
③ 返回多个检测结果的数组
④ 前端用左右滑动或网格展示各结果
```

**预计耗时**：4 小时  
**前置条件**：P0 完成

### P2：引导消息动态化

**目标**：欢迎消息根据用户状态动态变化。

| 用户状态 | 显示内容 |
|---------|---------|
| 首次访问 | 🌾 你好！上传照片开始检测 |
| 有历史记录 | 📋 上次检测到 [害虫名]，要再看看吗？ |
| 阴雨天气 | 🌧 近期降雨较多，注意稻飞虱爆发 |

**预计耗时**：2 小时

### P2：回答追问引导

**目标**：每次回答底部自动生成 2-3 个相关问题按钮。

**方案**：
```
① 在 LLM 系统提示词中要求输出 "followup_questions"
② 后端解析返回的 JSON，提取追问列表
③ 前端在回答底部渲染为快捷按钮
```

**预计耗时**：3 小时

### P3：离线能力探索

**目标**：弱网/无网环境下基本可用。

**方案**：Service Worker 缓存页面资源。

```
① 创建 sw.js，缓存 HTML/CSS/JS/Logo
② 在 index.html 中注册 Service Worker
③ 离线时显示"当前无网络，检测功能不可用"提示
④ 但用户可以看到本地历史记录
```

**预计耗时**：2 小时

## 明日优先级建议

```
立即开始（P0）
  └─ 检测历史 localStorage
      └─ 收益：用户体验质变，每次使用都有积累感

上午（P1）
  ├─ 首屏加载优化 ← 提升第一印象
  └─ 批量检测对比 ← 展示亮点

下午（P2）
  ├─ 引导消息动态化 ← 锦上添花
  └─ 回答追问引导 ← 提升交互深度

  └─ 离线能力 ← 长远价值
```

> **建议先从 P0 开始**——检测历史是用户最直接的"留存钩子"，有了历史记录，系统才从"一次性工具"变成"日常助手"。
